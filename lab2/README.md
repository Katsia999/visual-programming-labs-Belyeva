# Лабораторная работа 2 — Node-RED

Беляева Екатерина, СДП-ИИ-241. 12 обязательных потоков и ачивка №1 «Локальный MQTT».

## Запуск

1. Запустить Docker Desktop и дождаться работающего Docker Engine.
2. В PowerShell из папки `lab2` выполнить `./start.ps1`. Скрипт создаёт локальные данные, устанавливает Dashboard и Telegram-ноды и запускает контейнеры.
3. Открыть [редактор](http://localhost:1880) и [dashboard](http://localhost:1880/ui).
4. При первом запуске открыть конфигурацию Telegram bot и вставить свой токен от BotFather, затем нажать Deploy. Токен хранится в `runtime/node-red`, эта папка исключена из Git.

Повторный запуск контейнеров: `docker compose up -d`. Остановка: `docker compose stop`. Логи: `docker compose logs -f node-red`. Папка `runtime/node-red` подключена к `/data` контейнера и сохраняет потоки, установленные ноды, файл заказа и контекст.

Каждый JSON в `flows` можно импортировать отдельно через меню Node-RED → Import → select a file. Если потоки уже загружены, не нужно импортировать их второй раз.

## Ачивка 1

Конфиг брокера: `mosquitto/mosquitto.conf`. Внутри Docker Node-RED обращается к `mosquitto:1883`; с компьютера брокер доступен на `localhost:1883`. Редактор использует порт 1880. Порты опубликованы только на loopback компьютера.

Топик: `student/belyeva/lab2/local`. На вкладке 13 Inject каждые 5 секунд отправляет значение через Function → MQTT out. MQTT in подписан на этот же топик и передаёт полученное значение в Debug. Ноды должны показывать статус connected.

`allow_anonymous true` разрешает подключение без пароля в учебной локальной сети контейнеров. Публичный брокер находится в интернете, его обслуживает сторонняя организация, а доступность зависит от сети. Локальный брокер запускается на моём компьютере, его конфигурацию и жизненный цикл контролирую я; внешний интернет для обмена между двумя контейнерами не нужен.
