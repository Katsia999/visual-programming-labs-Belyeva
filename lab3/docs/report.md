## Новая сущность MealPlan

Внешний AI предложил сущность по следующему промпту:

```text
Предложи название и поля новой сущности для приложения Bubble «Каталог рецептов». Эта сущность должна отличаться от Recipe, созданной при первичной генерации. Нужна сущность для планирования приготовления блюда: название блюда, запланированная дата, отметка о приготовлении, количество порций и заметка. Укажи английские имена полей Bubble и их типы; нужны минимум три разных типа. Не создавай сущность автоматически: я добавлю её вручную в Data и внесу три записи через App Data.
```

В Data → Data types вручную создан MealPlan:

| Поле | Тип | Назначение |

| title | text | Название блюда |
| planned_date | date | Дата и время приготовления |
| is_cooked | yes/no | Отметка о приготовлении |
| servings | number | Количество порций |
| notes | text | Заметка |

![Тип MealPlan и поля](../screenshots/06-data-type.png)

## Страница meal_plans и workflows

[Dev-версия планов приготовления](https://my-app-261015-99229.bubbleapps.io/version-test/meal_plans). На неё ведёт кнопка «План приготовления» с главной страницы.

Промпт генерации новой страницы:

```text
В этом же приложении создай новую страницу meal_plans для уже существующего типа данных MealPlan. Не создавай второй тип с тем же назначением. Интерфейс на русском языке, структура header + body + footer, ссылка на главную и строка «ТВП: Беляева» в подвале.
Добавь форму с полями title (text), planned_date (date), is_cooked (yes/no), servings (number), notes (text). Добавь Repeating Group со списком MealPlan, выводом полей и кнопками «Просмотреть», «Изменить», «Удалить» для выбранной записи.
Создай отдельные workflows: «Создать» создаёт MealPlan из формы; «Просмотреть» показывает выбранную запись в группе подробностей; «Сохранить изменения» меняет только выбранный MealPlan; «Удалить» удаляет только выбранный MealPlan после подтверждения. Для удаления используй только демонстрационные записи этого приложения.
Не разрешай сохранение пустого названия и количества порций меньше 1. Сортируй список по planned_date. После создания и сохранения очищай форму; добавь отмену редактирования. Не используй внешние API или платные плагины.
```

Уточнение после первого ответа AI:

```text
Поле notes типа text уже создано вручную в MealPlan вместе с title, planned_date, is_cooked, servings. Перечитай актуальную схему; не создавай дубликаты полей и типов. Остальной план подходит. На главной странице добавь ссылку «План приготовления» на meal_plans, сохрани ручной заголовок «Книга рецептов — Екатерина» и стиль Recipe Primary Button с переменной recipe-primary.
```

В странице используются Input, Date/Time Picker, Checkbox, Multiline Input, Button, Repeating Group, группы подробностей, Popup подтверждения удаления и Alert ошибки. В custom states страницы хранятся выбранный и редактируемый MealPlan.

| Действие | Событие и шаги |
| --- | --- |
| Create | «Создать»: Create a new MealPlan с данными формы, затем Reset Form |
| Read | «Просмотреть»: записать текущую запись строки в состояние «Выбранный план», показать подробности |
| Update | «Изменить»: выбрать редактируемую запись; «Сохранить изменения»: Make changes to MealPlan, очистить состояние и форму |
| Delete | «Удалить»: передать выбранную запись в Popup; «Да, удалить»: удалить MealPlan из Popup, очистить связанные состояния и скрыть Popup |

Создание и сохранение разрешены только при непустом title после trim и servings ≥ 1. Для ошибочных значений предусмотрены отдельные workflows с Alert. На странице десять workflows с учётом отмены, подтверждения и ошибок.
